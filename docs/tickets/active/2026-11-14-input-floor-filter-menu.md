# Ticket: 更多菜单遮挡 / 筛选计数 / 同楼层输入只留最新

- 状态：等待本地验收
- 创建日期：2026-11-14
- 目标版本：不改版本号
- 发布权限：仅本地

## 目标

1. 「更多」弹出菜单不再被搜索框盖住。
2. 标签计数、角色卡计数与点进去的列表条数一致；只有用户输入的角色卡也能出现在「人物」里。
3. 同一聊天同一楼层反复发送/编辑输入时，只保留最新一次（标签合并到新记录）。

## 当前证据

- 主题槽重构给面板所有直接子层加了 `position: relative; z-index: 1`，header 和搜索行同级，后出现的搜索行盖住 header 里的弹层。
- 真实数据：标签「开局」书架显示 688，点进去列表只有 242（书架按原始版本计数，列表按楼层分组）。
- 角色卡统计把所有 user_input 归入 User 卡，例如只有输入没有摘录的卡（程肆川等）在「人物」里不出现；有摘录的卡计数只含摘录，点进去却连输入一起列出。
- 1642 条原始输入只显示为 797 组：同一楼层的旧版本一直累积。

## 允许修改

- `style.css`、`index.js`（仅四语言 scanPreview 文案）、`storage.js`、`server-plugin/tavern-notes/index.js`、`tests/user-input-floor-latest.cjs`

## 明确不做

- 不改数据格式；历史数据不自动清理，由用户在「输入整理 → 清除历史重复」预览后自己确认。
- 跨聊天、内容相同的输入不合并（不同聊天视为不同游玩）。

## 验收条件

- [x] 自动测试：`node --test tests/*.mjs` 46/46；新增 `tests/user-input-floor-latest.cjs` 通过。
- [x] 真实数据副本：5 个标签书架数 = 列表数；40 张角色卡计数 = 筛选列表数。
- [ ] 实机：打开「更多」菜单可点；同楼层重发后列表只剩最新一条；Lite 模式抽查一次。
