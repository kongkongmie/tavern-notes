# 二合一版本发布候选与浏览器测试交接

## 结论

**A. 自动验证通过，可以交给浏览器测试 Work。**

当前版本按本次约定正式冻结架构。后续测试只处理明确回归，不再以删除全部 `.tnl-*`、合并全部 CSS、统一变量前缀或合并完整入口为完成条件。

## 1. 本次版本真正改变了什么

- Full 成为公共界面、主题和公共交互代码的唯一维护来源。以后修改公共功能时，先改 Full，再由同步工具生成 Lite 的公共副本。
- Full 和 Lite 的主要面板、搜索筛选、笔记卡、标签、摘录、分享卡以及主题制作界面来自同一套公共生成逻辑，减少两边长期显示不一致的风险。
- 两边都保留主题选择、导入导出、融合和主题制作能力。
- 主题制作器现在使用独立草稿。融合当前酒馆主题、编辑 JSON 或直接关闭制作器，都不应悄悄改变正在使用的主题。
- “另存为”只保存新主题，不自动切换；“应用并保存”才保存并切换。
- Lite 的公共元素同时带有标准 `.tn-*` 和旧 `.tnl-*` 类。公共 JavaScript 使用标准类，旧类继续服务于现有 CSS 和用户自定义样式。
- Full 的文件存储、后端状态、安装引导、存储模式选择和打开主题文件夹能力继续保留。
- 独立 Lite 仍是兼容发行版，并继续识别原有浏览器数据；当统一版 Full 同时运行时，Lite 的共存守卫应阻止重复启动。

## 2. 没有改变什么

- 笔记数据格式没有改变。
- 独立 Lite 的 IndexedDB 名称仍是 `tavern-notes-lite`。
- Full 的文件存储位置和后端接口没有改变。
- 笔记和主题的导入导出格式没有改变。
- 原有设置键没有改变，包括独立 Lite 的 `tavern-notes-lite-settings`。
- 独立 Lite 的扩展名称、图标、安装目录、仓库地址和 manifest 身份没有改变。
- 没有自动迁移、合并或删除 Full/Lite 任一存储中的用户数据。

## 3. 必测运行组合

每个组合开始前记录：SillyTavern 版本、浏览器、屏幕宽度、已启用扩展、存储模式和是否已有旧数据。

### 组合 A：统一版 Full 文件模式

1. 只启用统一版 `tavern-notes`。
2. 选择 Full 文件存储。
3. 确认后端状态、文件模式标识、存储模式入口和“打开主题文件夹”可用。
4. 重启 SillyTavern 后再次确认数据和主题。

### 组合 B：统一版 Lite 浏览器模式

1. 只启用统一版 `tavern-notes`。
2. 选择 Lite IndexedDB 存储。
3. 确认无需 Full 后端即可新增和读取笔记。
4. 刷新页面和重启 SillyTavern 后再次确认数据。

### 组合 C：独立 Lite 兼容版

1. 禁用统一版。
2. 只启用独立 `tavern-notes-lite`。
3. 使用一份升级前已有的 Lite 数据进行验证。
4. 确认旧笔记、标签、设置、主题和字体记录仍能读取。
5. 确认不出现 Full 后端、安装引导或“打开主题文件夹”入口。

### 组合 D：统一版与独立 Lite 同时安装

1. 同时安装并启用两个扩展。
2. 刷新页面并观察入口、悬浮按钮和控制台。
3. 确认统一版优先运行。
4. 确认独立 Lite 的共存守卫生效，不出现第二套面板、重复按钮、重复监听或重复写入。

## 4. 必测功能

以下项目在 A、B、C 中都要测试；标注“专属”的项目只在对应组合测试。

### 启动与外观

- 扩展入口、品牌图标、主面板和悬浮按钮正常出现。
- Full 与 Lite 相同主题下的主要布局、间距、按钮位置和笔记卡外观一致。
- 切换日间、夜间以及现有内置主题后，主面板和动态笔记卡均正常。
- 在桌面宽度和移动宽度测试打开、关闭、滚动、弹层和输入框。
- Quick Reply 入口、显示条件、点击和关闭正常。
- Full 专属拖动光标仍显示 `grab` / `grabbing`，拖动行为正常。

### 笔记

- 新建普通笔记并保存。
- 打开详情页，核对正文、来源、角色、时间和标签。
- 编辑正文和标签并保存。
- 删除笔记并确认列表和计数更新。
- 搜索标题、正文或角色。
- 使用类型、角色和标签筛选；清除筛选后恢复完整列表。
- 刷新页面后确认数据仍存在。

### 摘录与整理

- 整层摘录按钮显示、hover、点击和关闭正常。
- 摘录正文不包含按钮、代码块或排除标签内容。
- 输入整理预览的统计和列表正确，取消不会修改数据，确认后结果正确。

### 导入导出与分享

- 导出全部、当前筛选范围以及 JSON/TXT。
- 导入刚导出的 JSON，核对数量、正文、标签和重复处理。
- 分享卡切换样式与背景。
- 图片导出成功，图片尺寸、字体、背景和文字没有截断。
- 导入本地字体后立即预览；刷新后的行为符合对应存储模式设计。

### 主题

- 普通主题选择会切换当前主题。
- 导入主题本身不会意外切换当前主题。
- 导出当前主题后能够重新导入。
- “融合当前酒馆主题”只产生制作器草稿，主界面当前主题不变。
- 修改草稿 JSON 后关闭制作器，当前主题不变。
- “另存为”保存主题但不激活。
- “应用并保存”保存并激活。
- Full 显示“打开主题文件夹”；统一版 Lite 模式和独立 Lite 不显示该入口。

### 兼容和共存

- 组合 C 验证升级前独立 Lite 的旧笔记、设置、主题和标签。
- 组合 D 验证共存守卫以及只有一套运行实例。
- 控制台不得出现重复初始化、空节点事件绑定、CSS 文件 404 或公共模块加载失败。

## 5. 已知高风险区域

1. **共享 CSS 加载**
   - `style.css` 通过 `@import` 加载 `shared/base.css`。检查网络面板不存在 404，并确认动态按钮和两套主题都获得共享样式。

2. **公共 App Shell 生成**
   - Full/Lite 包装层现在很薄，主体由公共生成器产生。重点检查版本专属入口没有串版、顺序没有变化、所有弹层挂载点存在。

3. **Lite 双类名兼容**
   - Lite 公共元素同时包含 `.tn-*` 和 `.tnl-*`。重点检查旧 Lite CSS、自定义 CSS和公共 JavaScript能同时工作。

4. **主题草稿隔离**
   - 融合、编辑 JSON、关闭、另存为、应用并保存的区别必须逐项验证，尤其注意关闭制作器后当前主题是否被污染。

5. **动态笔记卡类名**
   - 检查新生成和旧数据生成的笔记卡，包含菜单打开、详情、编辑和删除事件。

6. **标签与整层摘录类名**
   - 标签按钮和摘录按钮是动态生成的，检查刷新列表、切换筛选以及重新进入聊天后事件仍存在。

7. **分享卡选择器**
   - 检查主题选择、背景选择、即时预览以及导出图片。

8. **独立 Lite 发布包**
   - 检查共享文件被包含、相对路径正确、图标和 manifest 仍属于 Lite，并用真实安装目录验证。

## 6. 问题记录格式

每发现一个问题，单独记录：

```text
版本组合：

预期结果：
实际结果：
控制台错误：
是否可稳定复现：

```

严重级别建议：

- 阻塞：无法启动、数据损坏、无法保存、两个版本重复运行。
- 高：主要功能不可用、主题操作意外覆盖当前主题、导入导出错误。
- 中：特定入口或状态异常，但有替代路径。
- 低：不影响使用的轻微视觉差异或文案问题。
